# План: режимы TUI, перенос идей конкурентов, Tauri-фронтенд

**Цель.** (1) Довести терминальные режимы Lusty (одноколоночный уже есть;
нужны нормальные grid/multi-column и long), (2) перенести лучшие механики
fzf/telescope/skim, (3) добавить графический фронтенд на Tauri/web поверх
общего ядра — не ломая nvim-протокол `serve`.

**Критерий успеха.** Режимы переключаются и покрыты layout-тестами; лучшие
механики из research-фазы реализованы или явно отложены с причиной; GUI
собирается отдельно (`cargo` workspace member), использует `lusty-fuzzy` и
`lusty-core` как библиотеки; `cargo test` и serve-интеграционные тесты зелёные.

## Фаза 0 — сделано (эта сессия)

- Column-major сетка TUI: `grid_index`/`column_target`/`grid_offset`,
  `draw`, навигация и окно прокрутки согласованы; тесты в `src/tui.rs`.
- Фиксы ревью: `serve` Q-диапазон, UTF-8 truncate в preview, non-UTF8
  `meta_keys` и метки каталогов в кэше.

## Фаза 1 — сделано (эта сессия)

- Инвариант соблюдён: интеграционные тесты `serve` не менялись и зелёные,
  протокол байт-в-байт тот же.
- Проверка: `cargo test --workspace` (иначе тесты `lusty-core` не

- Осталось на потом: `pub`-поверхность `lusty-core` пока = прежние
  внутрикрейтовые `pub`-функции; сузить API имеет смысл перед фазой 4,
  когда появится второй потребитель.

## Фаза 2.5 — порт интерактивного слоя из fzf-navigator (сделано)

Источник: `fzf-navigator` (MIT, © Ben Ward) + модель панели у broot; атрибуция
и точная карта «что откуда» — в `CREDITS.md`.

- Инвариант «**одна таблица**»: `crates/lusty-core/src/keys.rs` — реестр
  действий (`Action::ALL` = порядок помощи), дефолтная раскладка, парсер
  `LUSTY_KEYS`/`--keys`, строки оверлея `?` и дамп `--key-map`. Диспетчер
  (`route_key`) и помощь читают его же, поэтому разъехаться не могут.
  Правила shell-версии сохранены: override **перемещает** действие, вторая
  запись того же действия даёт алиас, неизвестное имя/клавиша — одна строка
  предупреждения, остальной спек всё равно применяется.
- Инвариант «**печатаемое действие — тень символа**»: `/`, `[`, `\`, `?`
  срабатывают только на пустом промпте, иначе символ уходит в запрос
  (`type_into` — единственный путь символа в query). `,`, `.`, `/` и
  RU-раскладка (`б`→`,`, `ю`→`.`, `х`→`[`) покрыты тестами ввода и кадра.
- История каталогов (`history.rs`): новый визит обрезает forward-хвост,
  back/forward не заворачиваются, стартовый каталог достижим отовсюду — Esc
  сначала возвращает к старту и только там выходит.
- Флаги режима: `H`/`I`/`L`/`R` + `-N` (записи, скрытые точкой; один readdir
  на корень), `notice` для действий без видимого следа (copy/reload).
- `insert_selection` печатает пути **относительно каталога запуска** (не
  текущего корня) и `./` перед голым исполняемым именем; `copy_selection` —
  OSC 52 с shell-кавычками; в locked-режиме `exit` печатает `cd<TAB>path`.
- Иконки: `icon_theme.rs` читает тот же eza `theme.yml`, что и fzf-navigator
  (`$EZA_CONFIG_DIR`, `$XDG_CONFIG_HOME/eza/theme.yml`,
  `$XDG_CONFIG_HOME/lusty/icon-theme.yml`), плюс встроенная таблица частых
  расширений; точное имя бьёт расширение, длинный суффикс — короткий, тинт
  никогда не перекрывает foreground выделения (WCAG-инварианты целы).
- **`C-l` больше не крутит режим вида, а `C-r` не тогглит превью**: `C-l` —
  перерисовка, `C-r` — перечитывание каталога (как в less/mc), вид — `alt-v`,
  превью — `alt-p`, locked — `alt-l` (в shell-версии был `C-l`). Причина:
  цикл раскладки на `C-l` и панель на `C-r` — типичные «не то, что ждёт
  пользователь»; прежнее поведение возвращается строкой `LUSTY_KEYS`.
- Парность с Lua-клиентом: `--key-map` и `--icon-color-map` — дампы для
  смоук-скриптов nvim; сам клиент в этой сессии не менялся (только `src/` и
  `crates/`).
- Проверка: `cargo fmt --check`, `cargo clippy --workspace --all-targets --
  -D warnings`, `cargo test --workspace` (171 тест), плюс ручные дампы.

## Фаза 2 — нормальные режимы TUI

- Сделано: `ViewMode { List, Grid, Long }`, `--view list|grid|long` +
  `LUSTY_VIEW` (CLI важнее env), `alt-v` цикл по трём режимам (`C-l` с
  фазы 2.5 — перерисовка), `--long` —
  алиас `--view long`; дефолт `Grid` = прежняя адаптивная сетка.
  Раскладку задаёт `view_cols` (list/long — одна колонка, grid —
  адаптивные), `draw` рендерит в любой `Write`, поэтому режимы покрыты
  тестами кадра: list — одна запись в строке, grid — ≥2 колонки, long —
  поле прав перед именем.
- Сделано: подсветка выбранной ячейки на всю ширину колонки (сброс
  стиля после паддинга) и счётчик `matched/total` рядом с глубиной в
  промпте; тесты кадра меряют ширину подсвеченного спана и проверяют
  счётчик на пустом запросе (20/20) и на запросе без совпадений (0/20).
- Сделано: заголовок long-вида `PERM USER SIZE MODIFIED NAME` из
  `listing::meta_header(mask)` — ширины берутся из тех же констант, что и
  у `meta_line`, поэтому колонки сходятся; заголовок занимает первую
  строку выдачи (`list_rows` резервирует её). Тест сверяет позиции
  PERM/NAME с полями строки и число строк выдачи.
- Сделано: окно в одну строку выдачи (`--rows 4`) — полоса во всех
  режимах. `list_rows` — единственный источник правды, `view_cols`
  включает горизонтальную укладку при одной строке; meta-колонки и
  заголовок в полосе отключаются (43 ячейки meta в строку не влезают) и
  возвращаются на двух/трёх строках соответственно. Тесты по всем трём
  режимам + long на двух строках.
- Сделано: мультивыбор — `C-x` помечает запись и переходит к следующей,
  пометки живут как абсолютные пути в порядке пометки (переживают фильтр,
  сортировку и `C-w`), в промпте `+N`, Enter печатает по строке на каждую
  помеченную. Маркер — это `+` в одноколоночном поле плюс фон, то есть два
  независимых признака. Чистые `selection_paths`/`write_selection` покрыты
  тестами (порядок, fallback на курсор, non-UTF8 байты).
- Сделано: инварианты по цвету — `src/contrast.rs` (WCAG 2.1: luminance,
  contrast ratio, разбор SGR обратно в RGB), пороги-константы 4.5/3.0/1.5,
  тесты `contrast_invariants` на dim-тон, полосу выделения и её текст,
  нецветовую подсказку курсора, глиф `+` на его фоне и линию рамки; тема из
  `theme.toml` санируется по полям при загрузке (плохое значение падает в
  дефолт, а не в нечитаемый кадр).
- Preview: параметры в духе skim — позиция `right|left|up|down`,
  размер в `%`, `wrap`, `cycle`, `hidden`; env `LUSTY_PREVIEW_*`;
  асинхронный рендер уже есть, добавить защиту от шторма процессов
  (latest-wins).
- Тесты: чистая математика layout (колонки/окно/позиции) + смоук-скрипт.
- Проверка: `cargo test --workspace`, ручной смоук на большом дереве (`BENCH_ROOTS=/nix/store`).

## Фаза 3 — порт идей из research-фазы

Вход: 4 отчёта `docs/research/*.md` + сводная таблица impact/effort.
Кандидаты (уточняются отчётами): операторы запроса (`'`, `^`, `$`, `!`),

## Фаза 4 — Tauri/web фронтенд

- Новый workspace member `gui/lusty-gui`: `src-tauri` + фронтенд
  (Vite + TypeScript, без тяжёлого фреймворка).
- Backend: Tauri-команды поверх `lusty-core` (не через `serve`-протокол):
  `list(root, opts)`, `rank(query, sort, filters)`, `preview(index, w, h)`,
  `open(path)`, история/frecency. Для 600k записей — оконные выборки
  (индексы + `rank` в Rust, в JS не гоняем список целиком).
- Frontend: режимы list/grid/long, preview-панель, клавиатура как в fzf,
  подсветка спанов через `lusty_fuzzy::score_with_spans`, тема из
  `theme.toml`, мультивыбор.
- «Библиотека, которая есть»: `lusty-fuzzy` (скоринг/layout/spans/vectors)
  + `lusty-core` (обход/кэш/превью); JS-порт скорера не дублируем.
- Сборка: GUI не входит в дефолтный `cargo build` (feature `gui` или
  отдельный member с зависимостями только у себя); Nix-пакет отдельным
  output позже; webkit2gtk — только для GUI.
- Проверка: `cargo test` для core/bin не меняется; `cargo check` для GUI;
  smoke: открыть пикер, отфильтровать, превью, мультивыбор, открыть файл.

## Риски и решения

| Риск | Решение |
|---|---|
| Tauri тянет webkit2gtk и массу крейтов | отдельный member/feature, не в дефолтной сборке |
| IPC и 600k записей | rank/оконность в Rust, в JS — только видимый срез |
| Дублирование логики serve/GUI | общий `lusty-core`, протокол только для nvim |
| Смена поведения TUI ломает привычные клавиши | старые биндинги сохраняем, новые — добавка |
| Расползание объёма research | лимит ≤15 источников и ≤8+ механик на отчёт |
