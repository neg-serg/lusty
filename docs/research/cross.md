## Топ-механики для Lusty

- **Source-контракт (интерфейс источника вместо «файлового пикера»)** — mini.pick описывает источник как `{items, name, cwd, match, show, preview, choose, choose_marked}`: items может быть массивом, callable (вызывается один раз при старте в `cwd`) или `nil` (заполняется позже через `set_picker_items`); минимум — items, остальное — callbacks. snacks определяет source как `{finder, format, preview, actions, ...}`, а `sources` в конфиге — карта пресетов для конкретных источников. Переносить: в `lusty-core` трейт/структуру `Source {id, items: async, match, show, preview, choose}`; в `serve` — `source=<id>` в line-протоколе; в GUI — source-switcher. Сложность M. Источники: [mini.pick `MiniPick-source`](https://github.com/echasnovski/mini.nvim/blob/main/lua/mini/pick.lua), [snacks picker docs](https://github.com/folke/snacks.nvim/blob/main/docs/picker.md).
- **Мультивыбор с отдельным choose_marked** — mini.pick: mark/unmark элементов и `source.choose_marked(items_marked)`; choose возвращает `nil/false` = закрыть пикер, иное = продолжить (пример: открыть файл и остаться). snacks различает `confirm` (шорткат действия подтверждения) и обычные actions. Переносить: TUI — `Space`=mark, `Enter`=choose текущего, `C-a`=choose_marked; serve — расширение протокола видом `accept` vs `accept-marked`; GUI — batch-операции. Сложность M. Источники: [mini.pick `MiniPick-source.choose_marked`](https://github.com/echasnovski/mini.nvim/blob/main/lua/mini/pick.lua), [snacks picker config](https://github.com/folke/snacks.nvim/blob/main/docs/picker.md).
- **Адаптивные layout-пресеты с переключением в рантайме** — snacks: `layout.preset` — функция от ширины терминала (`vim.o.columns >= 120 and "default" or "vertical"`), `cycle=true`, действие `set_layout` и биндинги `layout_left/right/top/bottom` (`<c-w>H/J/K/L`); сами пресеты — `default` (list+preview 50%), `ivy` (bottom, height 0.4, preview width 0.6), `dropdown`, `bottom`. fzf-lua: `winopts.height/width/row/col`, `preview.layout = "flex"` c порогом `flip_columns = 100`, `preview.vertical="down:45%"`, `horizontal="right:60%"`. Переносить: TUI `ViewMode` + preview-позиция; порог ширины для переключения list/grid; GUI — те же пресеты как CSS-grid. Сложность M. Источники: [snacks layouts](https://github.com/folke/snacks.nvim/blob/main/docs/picker.md), [fzf-lua winopts](https://github.com/ibhagwan/fzf-lua/blob/main/README.md).
- **Подпись окна/список: title + live + flags и inline-инфо** — snacks в пресете `default`/`ivy` ставит заголовок окна `"{title} {live} {flags}"` (title по умолчанию — капитализированное имя source, `title_pos` left/center); fzf-lua ставит `["--info"] = "inline-right"` (счётчик fzf) и `title`/`title_pos`/`title_flags`; у preview — свой `title` (по умолчанию имя файла, `title_fnamemodify` режет до хвоста). Переносить: строка-заголовок `source · N matched/M total · sort/фильтр-флаги` в TUI; заголовок окна в serve-клиенте и GUI. Сложность S. Источники: [snacks layouts/format](https://github.com/folke/snacks.nvim/blob/main/docs/picker.md), [fzf-lua winopts/fzf_opts](https://github.com/ibhagwan/fzf-lua/blob/main/README.md).
- **Previewer как сменный модуль + защита от лагов** — fzf-lua разделяет `builtin` (Neovim-окно) и native fzf previewer'ы (`bat/cat/git`), поддерживает расширения (chafa/viu/ueberzugpp для изображений, treesitter-подсветку), `preview.delay = 20` мс («prevents lag on fast scrolling»), `wrap/hidden/scrollbar/scrolloff`, вложенные `preview.winopts` (number, cursorline, signcolumn). mini.pick: preview — callable `fun(buf_id, item)`, по умолчанию `MiniPick.default_preview`, обновляется при перемещении, скрыт по умолчанию с toggle. Переносить: `lusty-core` preview trait (text/image/ansi), дебаунс/latest-wins (в плане фазы 2 уже есть), GUI — render по типу. Сложность S/M. Источники: [fzf-lua previewers](https://github.com/ibhagwan/fzf-lua/blob/main/README.md), [mini.pick preview](https://github.com/echasnovski/mini.nvim/blob/main/lua/mini/pick.lua).

- **Frecency-движок (затухание вместо «просто счётчика»)**: формулы трёх реализаций.
  - **zoxide**: «Each directory… assigned a _score_, starting with 1 the first time it is accessed. Every subsequent access increases the score by 1». Frecency по времени последнего доступа: «Within the last hour: `score * 4`; within the last day: `score * 2`; within the last week: `score / 2`; otherwise: `score / 4`». Aging: при превышении `_ZO_MAXAGE` (env; default 10000) все оценки делятся на k, чтобы сумма стала ~90% MAXAGE, записи со score < 1 удаляются; «Theoretically, the maximum number of directories… is `4 * _ZO_MAXAGE`». Pruning: записи, которых нет на FS и старше 90 дней, удаляются лениво. Источник: [zoxide wiki, Algorithm](https://github.com/ajeetdsouza/zoxide/wiki/Algorithm), [zoxide README (env `_ZO_MAXAGE`, default 10000)](https://github.com/ajeetdsouza/zoxide/blob/main/README.md).
  - **telescope-frecency v1**: документированная формула `score = frequency * recency_score / max_number_of_timestamps`; age→value: 4 ч→100, 1 день→80, 3 дня→60, 1 неделя→40, 1 месяц→20, 90 дней→10; `max_timestamps` default 10. В 2.0.0 алгоритм заменён: «v1: count × static recency → v2: exponential decay» (README). Точная v2-формула из кода: `EntryV2:get_score(now) = score / 2^((now - reference_time) / half_life)`; при визите `set_score(score + 1, now) = (score + 1) * 2^((now - reference_time) / half_life)`, `num_accesses += 1`; default `half_life = 60 * 60 * 24 * 3` (3 дня). Источники: [telescope-frecency doc](https://github.com/nvim-telescope/telescope-frecency.nvim/blob/master/doc/telescope-frecency.txt), [README](https://github.com/nvim-telescope/telescope-frecency.nvim/blob/master/README.md), [v2/entry.lua](https://github.com/nvim-telescope/telescope-frecency.nvim/blob/master/lua/frecency/v2/entry.lua), [v2/table.lua](https://github.com/nvim-telescope/telescope-frecency.nvim/blob/master/lua/frecency/v2/table.lua).
  - **snacks.picker**: exponential decay, «Roughly based on Mozilla NewFrecency»; `HALF_LIFE = 30 дней`, `λ = ln(2)/half_life`, хранится «deadline»: `t = now + ln(s)/λ`, чтение: `s = e^(λ*(deadline − now))`; визит прибавляет +1 (комментарий: «typed=2, clicked=1»), seed для новых записей: `value · e^(−λ·dt)` от mtime/lastused; frecency каталога = сумма frecency файлов внутри; `MAX_STORE_SIZE = 10000` (хранилище — sqlite, fallback kv). Бонус к скорингу ограничен: `score += (1 − 1/(1 + frecency)) * 8` — максимум +8, т.е. frecency не перебивает качество матча. Источники: [core/frecency.lua](https://github.com/folke/snacks.nvim/blob/main/lua/snacks/picker/core/frecency.lua), [core/matcher.lua](https://github.com/folke/snacks.nvim/blob/main/lua/snacks/picker/core/matcher.lua). fzf-lua отдаёт это внешнему zoxide: команда `:FzfLua zoxide` = «list recent directories» ([fzf-lua README](https://github.com/ibhagwan/fzf-lua/blob/main/README.md)).
  Переносить в Lusty: `core`: модуль frecency (score + last_access + decay-λ, bounded bonus как tiebreak, а не замена fzy); источник «recent/zoxide»; `serve`: ранжирование и история; `GUI`: история/частые файлы. Сложность M. Открытый вопрос — своя БД Lusty или чтение zoxide DB (см. ниже).
- **Async-конвейер и кэш матчей** — snacks: «Finders and matchers run asynchronously for maximum performance»; ограничения `limit_live = 10000`, `show_delay = 5000` (мс до индикации загрузки), матчер добровольно уступает через `YIELD_MATCH = 1` мс. mini.pick: `items`-callable раскручивается через `vim.schedule` — «Set items on next event loop to not block when computing stritems»; кэш матчей опционален: `options.use_cache` = «cache match results per prompt… faster response on repeated prompts… at the cost of using more memory. Default: false». fzf-lua гасит шторм превью `preview.delay = 20` мс. Переносить: `serve` — стриминг частичных результатов и отмена по новому запросу; `core` — chunked matcher + query-cache с лимитом; `GUI` — отмена через job-id. Сложность M. Источники: [snacks](https://github.com/folke/snacks.nvim/blob/main/docs/picker.md), [mini.pick](https://github.com/echasnovski/mini.nvim/blob/main/lua/mini/pick.lua), [fzf-lua](https://github.com/ibhagwan/fzf-lua/blob/main/README.md).

## Best-of конфигурации

- **fzf-lua — профили и композиция** (README): базовая настройка профилем `setup({'fzf-native'})`; телескоп-вид с bat-превью `setup({"telescope", winopts={preview={default="bat"}}})`; комбинирование профилей `setup({{"telescope","fzf-native"}, winopts={fullscreen=true}})`. Составные пикеры: `:FzfLua combine pickers=oldfiles;git_files`; универсальный вход `:FzfLua global` с префиксами `$`/`@`/`#`. Источник: [fzf-lua README](https://github.com/ibhagwan/fzf-lua/blob/main/README.md).
- **snacks.picker — «general»-раскладка** (docs): «Top Pickers & Explorer» — `<leader><space>` = `Snacks.picker.smart()` (Smart Find Files), `<leader>,` = buffers, `<leader>/` = grep, `<leader>e` = explorer, `<leader>fr` = recent. Готовые пресеты источников: `recent_projects` c `matcher = { frecency = true, sort_empty = true }` и `sort = { fields = { "score:desc", "idx" } }`, confirm = `load_session`; `files` c `cwd_bonus`/`frecency`; explorer-биндинги `a`/`d`/`r`/`m`/`c`/`p` (add/del/rename/move/copy/paste) и `u` (update). Layout-пресеты `ivy`/`dropdown`/`bottom` из коробки + `preset` по ширине. Источник: [snacks picker docs](https://github.com/folke/snacks.nvim/blob/main/docs/picker.md).
- **mini.pick — минимальный вход**: `MiniPick.start({ source = { items = vim.fn.readdir('.') } })`; для тяжёлых списков `use_cache = true` (память ↔ скорость); кастомный матчер-пример из доки — regex-фильтр: `local prompt_pattern = vim.pesc(table.concat(query)); local f = function(i) return stritems[i]:find(prompt_pattern) ~= nil end`. Источник: [mini.pick](https://github.com/echasnovski/mini.nvim/blob/main/lua/mini/pick.lua).
- **oil.nvim**: `columns = { "icon" }`, `delete_to_trash = false` (заменить на `true` для безопасности), `preview_split = "auto"`, `g.` = toggle_hidden, `g\` = toggle_trash, `prompt_save_on_select_new_entry = true` (не терять несохранённые правки). Источник: [oil.nvim README](https://github.com/stevearc/oil.nvim/blob/master/README.md).
- **telescope-frecency**: `:Telescope frecency workspace=CWD path_display={"shorten"} theme=ivy`; для отладки `show_scores = true`; workspace-фильтр ограничивает кандидатов каталогом (неиндексированным файлам даётся score 0). Источник: [telescope-frecency doc](https://github.com/nvim-telescope/telescope-frecency.nvim/blob/master/doc/telescope-frecency.txt).

## Антипаттерны / что не тащить

- **Комбинировать пикеры разных типов записей.** fzf-lua прямо предупреждает: «To avoid errors combine only pickers of the same entry types (i.e files)» — иначе ломаются форматтер/превью, унаследованные от первого пикера. Для Lusty: combine только внутри одного `Source`-типа (Entry одинаковой формы). [fzf-lua](https://github.com/ibhagwan/fzf-lua/blob/main/README.md).
- **Вторая система скоринга.** snacks `score.lua` — явный порт fzf-скоринга (`SCORE_MATCH=16`, `SCORE_GAP_START=-3`, …); тащить её рядом с `lusty-fuzzy` (fzy) — двойная поддержка и несовместимые golden vectors. Переносить только frecency-tiebreak (bounded +8) поверх существующего скоринга. [snacks score.lua](https://github.com/folke/snacks.nvim/blob/main/lua/snacks/picker/core/score.lua), [core/matcher.lua](https://github.com/folke/snacks.nvim/blob/main/lua/snacks/picker/core/matcher.lua).
- **Frecency без aging/лимита/исключений.** zoxide вынужден держать `_ZO_MAXAGE` (default 10000, нормировка до ~90%, удаление score<1) и ленивый pruning >90 дней; snacks — `MAX_STORE_SIZE=10000`; telescope-frecency — ручные `:FrecencyDelete`/`:FrecencyValidate`. Без этого БД растёт и продвигает мусор. [zoxide wiki](https://github.com/ajeetdsouza/zoxide/wiki/Algorithm), [snacks frecency](https://github.com/folke/snacks.nvim/blob/main/lua/snacks/picker/core/frecency.lua).
- **Необратимые FS-мутации из пикера без подтверждения.** oil держит confirmation-окно, trash-режим, `prompt_save_on_select_new_entry`; удалять/переименовывать из Lusty без preview-подтверждения и undo нельзя. [oil README](https://github.com/stevearc/oil.nvim/blob/master/README.md).
- **Тяжёлые image/ANSI-превью в базовую сборку.** chafa/viu/ueberzugpp у fzf-lua — optional dependencies; для Lusty core/TUI это должно быть опцией с fallback, иначе Nix-сборка и headless `serve` потянут лишнее. [fzf-lua](https://github.com/ibhagwan/fzf-lua/blob/main/README.md).
- **БД, тянущая нативные либы из сети.** snacks db: «path to the sqlite3 library… If not set, it will try to load the library by name. On Windows it will download the library from the internet» — для offline/Nix-пакета неприемлемо; Lusty-стору нужен чистый file-format (kv/json) без загрузок. [snacks db config](https://github.com/folke/snacks.nvim/blob/main/docs/picker.md).
- **Профиль «hide» без оговорок.** fzf-lua предупреждает: дефолт включает hide, Esc терминирует fzf, и resume «limited» — при переносе resume в Lusty явно фиксировать семантику Esc и «скрыть/восстановить». [fzf-lua](https://github.com/ibhagwan/fzf-lua/blob/main/README.md).
- **Кэш матчей по умолчанию.** mini.pick сознательно держит `use_cache = false` (память важнее для дефолта) — не включать безлимитный кэш по запросу в долгоживущем `serve`. [mini.pick](https://github.com/echasnovski/mini.nvim/blob/main/lua/mini/pick.lua).

## Открытые вопросы

1. **Своя frecency-БД Lusty или чтение zoxide DB?** zoxide, telescope-frecency и snacks пишут каждый в свой store; не проверял, какой из форматов пригоден для чтения Rust-стороной и нужен ли импорт-миграция. Решение влияет на `core`/`serve`.
2. **Куда именно вешать frecency-бонус:** snacks использует `(1 − 1/(1+f)) * 8` поверх собственного скоринга; для fzy-скоринга Lusty эквивалент не калиброван — нужен эксперимент на golden vectors (не проверено).
3. **v2-миграция telescope-frecency:** `half_life` default 3 дня подтверждён только в коде `v2/table.lua`; как именно конвертируются v1-записи (`num_accesses` теряют историю timestamps) — не сверял построчно с migration-кодом.
4. **Resume/combine в line-протоколе `serve`:** ни fzf-lua, ни snacks не дают протокола для внешнего клиента; дизайн `resume`/`source`/`combine` сообщений для Neovim-плагина не проверен ни на одном конкуренте.
5. **RU→EN и операторы:** snacks использует `:`/`'`/`$`/`--` как служебные символы; не проверено, как раскладка-конвертер Lusty должна решать конфликт `:` (field-префикс) и `'` (exact-оператор) при русской раскладке.
6. **Мультивыбор в `serve`:** у mini.pick `choose_marked` возвращает «продолжать/закрыть»; в line-протоколе Lusty нет подтверждённого способа вернуть несколько путей и признак продолжения.
7. **Адаптеры SSH/S3 (oil):** покрываются ли они «TUI+serve» скоупом Lusty или это заведомо вне рамок — решение за roadmap, не за отчётом.
8. **Grid/long × preview:** конкуренты все одноколоночные (list); как preview-панель сочетается с сеткой (фаза 2 плана Lusty) — прямых источников нет, нужен собственный layout-тест.
