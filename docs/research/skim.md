## Карта возможностей

**Что это.** skim-rs/skim — fuzzy finder, «реализованный с нуля на Rust» (не форк кода fzf), MIT. Актуальная версия на дату отчёта — 5.7.4 (2026-10-04): ~2.07 млн загрузок crates.io и 138 reverse dependencies (пакет `skim` как библиотека); GitHub API на 2026-10-14: 6993★, 262 форка, 9 открытых issue, репозиторий создан 2016-05-29. Источники: [crates.io](https://crates.io/crates/skim), [GitHub API](https://api.github.com/repos/skim-rs/skim).

**История адресов (проверено, а не по памяти).** Старый адрес `lotabout/skim` в GitHub API перенаправляется на `skim-rs/skim` — тот же repository id (`59929513`), т.е. это переименование/перенос владельца, а не форк. Организация `skim-org` существует (создана 2022-09-13), но публичных репозиториев у неё 0 (GitHub API: `public_repos=0`), репозитория `skim-org/skim` API не показывает. Формулировку «lotabout/skim → skim-org/skim» источники не подтверждают: канонический репозиторий — `skim-rs/skim`; роль skim-org вынесена в открытые вопросы. Источник: [api.github.com/repos/lotabout/skim](https://api.github.com/repos/lotabout/skim) (HTTP-редирект на repositories/59929513), [api.github.com/orgs/skim-org](https://api.github.com/orgs/skim-org), [api.github.com/orgs/skim-org/repos](https://api.github.com/orgs/skim-org/repos).

**Режимы/UI.** Один список (одна колонка); есть `--multiline`, `--wrap`, скроллбар, `--layout default|reverse|reverse-list`, `--height`, `--margin`, `--border`, `--popup` (alias `--tmux`), `--image` (halfblocks). Никаких grid/columns/long-режимов нет — это зона, где Lusty уже впереди, у skim нечего заимствовать по компоновке. Источник: [man sk.1](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1) (LAYOUT/DISPLAY), [src/options.rs](https://github.com/skim-rs/skim/blob/v5.7.4/src/options.rs).

**Экосистема.** (1) Библиотека `skim` с публичным API `SkimOptionsBuilder`/`Skim::run_with` и 20 примерами в `examples/`; CLI-часть отделена feature-флагом `cli` — для библиотечного использования рекомендуют `default-features=false`. (2) Vim-плагин `plugin/skim.vim` (в шапке — Copyright Junegunn Choi, адаптация из fzf.vim, MIT) и запуск popup через `bin/sk-tmux`. (3) Shell-биндинги/комплиты: `shell/key-bindings.{bash,zsh,fish}`, `completion.{bash,zsh,fish,nu}` и генератор `sk --shell <shell> --shell-bindings`. (4) Внешние фронтенды: README документирует профиль skim в neovim-плагине fzf-lua. Источники: [Cargo.toml](https://github.com/skim-rs/skim/blob/v5.7.4/Cargo.toml), [examples/](https://github.com/skim-rs/skim/tree/v5.7.4/examples), [plugin/skim.vim](https://github.com/skim-rs/skim/blob/v5.7.4/plugin/skim.vim), [bin/sk-tmux](https://github.com/skim-rs/skim/blob/v5.7.4/bin/sk-tmux), [shell/](https://github.com/skim-rs/skim/tree/v5.7.4/shell), [README](https://github.com/skim-rs/skim/blob/v5.7.4/README.md).

**Отличия от fzf (по первоисточнику).** README перечисляет: (1) interactive mode, (2) pre-selection, (3) другой алгоритм; «командные флаги могут отличаться». Практические расхождения, проверенные по man/source v5.7.4: `--expect` помечен deprecated и заменён на `accept(<key>)`-биндинги; в списке actions нет `transform` и `change-preview-window`; в грамматике `--preview-window` нет `cycle`/`follow`/border-токена (рамка — отдельный `--border`); `--tmux` — это alias `--popup`. Источники: [README, Differences from fzf](https://github.com/skim-rs/skim/blob/v5.7.4/README.md), [man sk.1](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1) (KEYBINDS/Actions, PREVIEW, DEPRECATED), [src/options.rs](https://github.com/skim-rs/skim/blob/v5.7.4/src/options.rs) (alias `tmux`).

## Топ-механики для Lusty

Ниже — механики в порядке ценности для Lusty. Сложность: S — день-два, M — небольшая фича/PR, L — архитектурная работа. «Источник» — первоисточник (man v5.7.4 или файл v5.7.4); секции man цитирую по имени.

- **Выходной контракт (`SkimOutput`) + `accept(<key>)`** — `Skim::run_with` возвращает `SkimOutput` с `query`, `cmd`, `selected_items`, `current`, `final_key`, `final_event`, `is_abort`; CLI-флаги `--print-query`, `--print-cmd`, `--print-score`, `--print-header`, `--print-current`, `--output-format` (перекрывает все `print_*`), `--read0`/`--print0`, `--select-1`/`--exit-0`, exit codes 0/1/130. Ключ, которым приняли выбор, уходит в `final_key`, а `accept(key)` печатает свой аргумент — это замена deprecated `--expect`. Что переносить: **serve/core** — Q-ответ уже отдаёт query/rows, но не «каким ключом приняли» и не current/score; Neovim-клиенту это нужно для «edit vs split vs tab» без второго запроса, GUI — для маршрутизации действий. Сложность **S/M** (расширение протокола + поле в ядре). Источник: [man sk.1, SCRIPTING/DEPRECATED/EXIT CODES](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1), [src/output.rs](https://github.com/skim-rs/skim/blob/v5.7.4/src/output.rs).

- **Библиотечный lifecycle и каналы (`Skim::run_with`/`init`/`enter`/`run_until`)** — `Skim::run_with(options, Option<SkimItemReceiver>)` прогоняет пикер на готовом потоке; есть `run_items(options, items)` для итератора, fine-grain режим `init → start → init_tui → enter → run_until` с `event_sender()` и `Event::ClearItems` (пример fine-grain.rs каждую секунду подменяет выдачу). Поток элементов — батчи `Vec<Arc<dyn SkimItem>>` через `kanal` (`SkimItemSender`/`SkimItemReceiver`; README говорит «crossbeam», но в v5.7.4 source — `kanal`, т.е. README устарел); `SkimItemReader::of_bufread(BufRead)` строит источник, `SkimItem` реализован для `AsRef<str>`. Что переносить: **core** — именно эта развилка нужна Lusty: `Core::run_with(options, source_rx)` + источник-абстракция, поверх которой TUI, `serve`-адаптер и Tauri-GUI (без дублирования логики); события (items changed / query changed / preview ready) вместо прямых вызовов. Сложность **L** (совпадает с фазой 1-2 плана). Источники: [src/skim.rs](https://github.com/skim-rs/skim/blob/v5.7.4/src/skim.rs), [src/lib.rs (типы каналов, ItemPreview)](https://github.com/skim-rs/skim/blob/v5.7.4/src/lib.rs), [examples/fine-grain.rs](https://github.com/skim-rs/skim/blob/v5.7.4/examples/fine-grain.rs), [README «Use as a library»](https://github.com/skim-rs/skim/blob/v5.7.4/README.md).

- **Preview как часть айтема (`SkimItem::preview`) — не только shell** — трейт `SkimItem` даёт `text()`, `display(DisplayContext)`, `preview(...) -> ItemPreview`, `output()`, `get_matching_ranges()`, `hidden_ranges()`, `disabled()`. `ItemPreview` = `Command(String) | Text(String) | AnsiText(String) | CommandWithPos(..) | TextWithPos(..)`. Что переносить: **core/GUI** — абстракция `PreviewProvider` на уровне Entry: TUI исполняет Command в процессе, GUI рендерит Text/AnsiText без спавна, а выделенные спаны (`get_matching_ranges`) подсвечивает тот же код, что и список. Это снимает главный риск «GUI через shell». Сложность **M**. Источники: [src/skim_item.rs](https://github.com/skim-rs/skim/blob/v5.7.4/src/skim_item.rs), [src/lib.rs](https://github.com/skim-rs/skim/blob/v5.7.4/src/lib.rs).

- **Реестр действий + `--bind`** — `--bind` принимает `trigger:action[+action]`; trigger — клавиша, `double-click`, событие (`change`, `start`, `load`, `result`, `focus`, `zero`, `one`) или имя действия с префиксом `act-` (`act-up:last`); действий 70+ (`accept`, `abort`, `reload`, `execute(-silent)`, `toggle-sort`, `toggle-preview(-wrap)`, `refresh-preview`, `set-query/-header/-preview-cmd`, навигация, `select-all`/`toggle-all`, `if-query-empty/not-empty`, `if-non-matched`, `suppress`, `ignore`, `unbind`…). Что переносить: **core** — `Action` enum + парсер bind-строк + резолвер конфликтов; **TUI** и **GUI** диспатчат одни и те же actions; **serve** получает подмножество как запросы `A <action>` (по аналогии с существующим `X preview` capability). Сложность **M**. Источник: [man sk.1, KEYBINDS/Actions](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **Цепочки и follow-up триггеры, `suppress`, runtime `bind`/`unbind`** — действия склеиваются `+` (`ctrl-a:select-all+accept`); цепочка на имя действия срабатывает после него, но не рекурсивно (noremap-семантика); `act-up:suppress+down` отменяет дефолт действия. Что переносить: **core** — цепочки и нерекурсивность стоят дёшево, runtime-перепривязка (`bind()`) — дорого по blast radius, её лучше отложить; в Lusty достаточно статического keymap + цепочек. Сложность **M** (без runtime — S). Источник: [man sk.1, KEYBINDS](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **Command-actions и условные ветки** — `execute(cmd)` переключает alternate screen, `execute-silent(cmd)` не переключает, но UI не отвечает до конца команды (асинхронность — только через `&`); `reload([cmd])`, `refresh-cmd`, `refresh-preview`, `set-query/set-header/set-preview-cmd`, `if-query-empty`, `if-query-not-empty`, `if-non-matched`. Что переносить: **TUI/serve/GUI** — как маленький реестр внешних эффектов (открыть, перечитать каталог, обновить превью); в `lusty-core` держать только планировщик/типы, сам спавн — на фронтендах; превью и reload обязаны быть latest-wins, иначе шторм процессов. Сложность **M** (TUI), **S** (типы в core). Источник: [man sk.1, INTERFACE/Actions](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **Interactive mode (`-i`/`--interactive`, `--cmd`, `{q}`/`{}`)** — команда запускается на изменение запроса (`sk --ansi -i -c 'ag --color {q}' --preview "preview.sh {}"`), `Ctrl-Q` (по умолчанию) — `toggle-interactive`, промпт `c>`; отдельные `--cmd-query`, `--min-query-length` (команда не дёргается на коротком запросе), `--cmd-history`; `{}` подставляется в команды. Что переносить: **core** — источник типа «команда от запроса» (grep/буферы/LSP) с debounce и min-length; **TUI** — режим с индикатором `c>`; **serve** — источник задаётся клиентом. Сложность **M** (ядро источника), **S/M** (TUI). Источники: [man sk.1, MODES/INTERFACE](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1), [README, Interactive mode](https://github.com/skim-rs/skim/blob/v5.7.4/README.md).

- **Грамматика `--preview-window`** — формат `[up|down|left|right][:SIZE][:hidden][:[no]wrap][:[no]pty][:+SCROLL[-OFFSET]]`, default `right:50%`; SIZE: `0` прячет, положительное — строки/проценты, отрицательное — «всё, кроме превью»; `:hidden` прячет до `toggle-preview`; `+SCROLL` и `{2}-/2` дают начальный скролл к строке (кейс git grep, man пример); на Linux превью идёт в PTY, когда wrap выключен. Что переносить: **TUI** — Lusty уже умеет правую панель (`LUSTY_PREVIEW_WIDTH`), добавить позиции up/down, долю в %, hidden, wrap, начальный скролл; **GUI** — та же модель панели; в core — только типы/парсер, не UI. Сложность **S/M**. Вним.: `cycle`, `follow` и border-токен в грамматике v5.7.4 отсутствуют (см. открытые вопросы). Источник: [man sk.1, PREVIEW](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **Действия превью** — `toggle-preview`, `toggle-preview-wrap`, `refresh-preview`, `set-preview-cmd`, `preview-up/down/left/right`, `preview-page-up/down`. Что переносить: **TUI/GUI** — Lusty имеет только toggle; добавить refresh и прокрутку дёшево (панель уже построчная), set-preview-cmd пригодится GUI. Сложность **S**. Источник: [man sk.1, Actions](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **`--listen`/`--remote`: внешнее управление через сокет** — сервер слушает именованный сокет (`interprocess`), принимает Actions/цепочки в формате, «соответствующем Actions» (в v5.7.4 для библиотеки — RON через serde; `sk --remote` читает строки-цепочки со stdin: `echo 'up+select-row' | sk --remote`); feature `listen` выключен в библиотечном профиле. Что переносить: **serve** — идея «управлять запущенным пикером снаружи» уже почти есть в line-протоколе; можно добавить control-socket для тестов и «открыть выбранное в GUI»; в core — не тащить, это отдельный feature-модуль. Сложность **L**; отложить, но держать в дизайне протокола (действия как данные). Источники: [man sk.1, LISTEN/REMOTE](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1), [Cargo.toml (feature listen)](https://github.com/skim-rs/skim/blob/v5.7.4/Cargo.toml).

- **Options builder + typed enums + feature-gating** — `SkimOptionsBuilder` с методами (`.height("50%").multi(true)`), типизированные `FuzzyAlgorithm`, `RankCriteria`, `TuiLayout`, `PreviewLayout`, `CaseMatching`; `default = ["cli","frizbee","image","listen"]`, но в README прямо сказано, что `cli` библиотеке «should not be needed», а пример — `default-features=false`. Что переносить: **core** — `lusty-core::Options` + builder, общий для TUI/serve/GUI; clap-типы не должны протекать в библиотеку (в skim они за feature `cli`); GUI-зависимости — отдельным feature/member (уже в плане Lusty). Сложность **M**. Источники: [Cargo.toml](https://github.com/skim-rs/skim/blob/v5.7.4/Cargo.toml), [README «Use as a library»](https://github.com/skim-rs/skim/blob/v5.7.4/README.md), [src/options.rs](https://github.com/skim-rs/skim/blob/v5.7.4/src/options.rs).

- **Сменные алгоритмы матчинга и схемы** — `--algo arinae` (default, «latest»), `skim_v2`, `clangd`, `fzy`, `frizbee`; `--typos` (адаптивно `pattern_length/4`) / `--no-typos`; `--scheme default|path|history` (path — искать дальше по пути и приоритизировать pathname-тайбрейк, history — принудительно index первым тайбрейком). Что переносить: **core/lusty-fuzzy** — enum/трейт алгоритма поверх существующего fzy-скорера + пресеты схем (`path` для файлов, `history` под frecency); typo-tolerance — крупная отдельная тема, не в первую волну; golden vectors остаются арбитром. Сложность **M** (схемы), **L** (новые матчеры). Источник: [man sk.1, OPTIONS](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **Операторы запроса** — пробел = AND, `|` = OR, `'` = exact-термин (в `--exact` режиме наоборот отключает exact), `^`/`$` = анкеры, `!` = отрицание; в changelog 5.7.4 отмечен inverse prefix `!^`. Что переносить: **core/lusty-fuzzy** — парсер термов поверх скорера со спанами; учесть RU→EN раскладку (у Lusty своя механика) и добавить golden vectors на каждый оператор. Сложность **M**. Источники: [man sk.1, SEARCH](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1), [CHANGELOG 5.7.4](https://github.com/skim-rs/skim/blob/v5.7.4/CHANGELOG.md).

- **Tiebreak и управление порядком** — `--tiebreak score,begin,end` (default, порядок критериев), критерии `score/begin/end/length/index`, каждый можно инвертировать (`-index`), дубли запрещены; `--no-sort` + `--tac` для внешнего порядка (`history | sk --tac --no-sort`); схема `history` форсирует index первым. Что переносить: **core/rank** — цепочка tiebreak-критериев в `lusty-core`, `--no-sort` как режим «сохранить порядок источника» (полезно для буферов/недавних), index как основу frecency. Сложность **S/M**. Источник: [man sk.1, OPTIONS/SEARCH](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **Мультивыбор, пре-селекция и fast paths** — `--multi` (Tab/S-Tab), `select`/`toggle`/`select-all`/`deselect-all`/`toggle-all`/`toggle-in/out`; пре-селекция `--pre-select-n`, `--pre-select-pat` (regex), `--pre-select-items`, `--pre-select-file`; `--select-1` (не входить в TUI, если ровно одно совпадение), `--exit-0`, `--sync` (сначала дочитать поток — для `sk --multi | sk --sync`). Что переносить: **TUI** — мультивыбор в grid/long (в nvim-клиенте уже есть marks — перенести состояние в общий core); **serve** — Q уже несёт mask; добавить pre-select и select-1 как экономию запросов; **GUI** — чекбоксы. Сложность **M** (TUI), **S** (core Options). Источник: [man sk.1, INTERFACE/SCRIPTING](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **История запросов и команд** — `--history <file>` (+ `--history-size` 1000) грузит и дописывает историю запроса, `--cmd-history` — историю команд interactive-режима; при включении Ctrl-N/Ctrl-P автоматически ремапятся на `next-history`/`previous-history`; есть одноимённые actions. Что переносить: **core/TUI/serve** — у Lusty сейчас только «последний запрос» в XDG state; добавить журнал запросов с лимитом и next/prev, а также историю команд (позже — interactive source); frecency `F` в serve уже есть, её стоит связать с history-схемой. Сложность **S/M**. Источник: [man sk.1, HISTORY](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **Layout/height/margin/popup/cycle** — `--layout default|reverse|reverse-list`, `--height` в строках или % (отрицательное = term_height − N), `--no-height`, `--min-height` (только строки; «ignored when --height is not specified»), `--margin TRBL` (строки/% на сторону), `--cycle` (зацикливание списка), `--popup` с alias `--tmux` (detect Zellij → Tmux, вложенные сессии — Zellij приоритетнее), плюс wrapper `bin/sk-tmux`. Что переносить: **TUI** — height/margin/reverse и cycle (дёшево, полезно для nvim-флоата); **standalone** — `--popup` alias как готовый приём запуска в tmux; сетки/колонок у skim нет, не источник для grid/long. Сложность **S/M** (кроме popup-интеграции — M). Источники: [man sk.1, LAYOUT/DISPLAY](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1), [src/options.rs (alias tmux)](https://github.com/skim-rs/skim/blob/v5.7.4/src/options.rs), [bin/sk-tmux](https://github.com/skim-rs/skim/blob/v5.7.4/bin/sk-tmux).

- **Метаданные: `--nth`/`--with-nth`/`--hide-nth` + field index expressions** — предметом матчинга могут быть выбранные поля (`--delimiter ':' --nth 1`), порядок отображения меняет `--with-nth`, скрытие — `--hide-nth`; в командах превью поддерживаются expressions `{1}`, `{-1}`, `{-4..-2}` и offset-формы (`{2}-/2`). Что переносить: **core** — модель «match text vs display text vs output text» (пригодится long/grid-колонкам и превью по строке: grep-строка → файл+номер); **serve** — не расширять до shell, но expressions полезны для M/V запросов. Сложность **M**. Источник: [man sk.1, OPTIONS/COMMAND EXPANSION/FIELD INDEX EXPRESSION](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1).

- **Оформление, статус и env-конфиг** — `--color`, `--border none|plain|rounded|…` (отдельно от превью), `--header`/`--header-lines`, `--info`/`--inline-info`/`--no-info` (счётчик matched/total), `--scrollbar`, `--multiline`, `--keep-right`, `--highlight-line`; env: `SKIM_DEFAULT_COMMAND` (fd → git ls-tree → rg --files → ag → find), `SKIM_DEFAULT_OPTIONS`, `SKIM_OPTIONS_FILE`, `NO_COLOR`. Что переносить: **TUI/GUI** — theme.toml Lusty уже есть, добавить заголовок/счётчик и грамматику options-файла (пресеты); GUI берёт те же токены. Сложность **S/M**. Источники: [man sk.1, DISPLAY/THEME/ENVIRONMENT VARIABLES](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1), [plugin/skim.vim (SKIM_DEFAULT_COMMAND)](https://github.com/skim-rs/skim/blob/v5.7.4/plugin/skim.vim).

## Best-of конфигурации

Примеры из первоисточников (v5.7.4), которые выглядят переносимыми в Lusty.

- **Interactive + preview (grep-пайплайн):** `sk --ansi -i -c 'ag --color {q}' --preview "preview.sh {}"` — README, раздел Preview Window. Аналог для Lusty: `--interactive`-источник из `rg`/git-grep + превью текущей строки.
- **Файловый браузер одним биндом:** `sk --bind "enter:execute(less {})"` — man, INTERFACE. В Lusty: `enter` = открыть в Neovim, `ctrl-o` = split, `ctrl-v` = vsplit (сейчас это в nvim-клиенте, но ядро действий не имеет).
- **Комбинированный бинд с фоном:** `sk --bind 'f1:execute(less -f {}),ctrl-y:execute-silent(echo {} | pbcopy)+abort'` — README, Key Bindings. Цепочка `execute-silent + abort`.
- **Мультивыбор и приём пачки:** `sk --bind 'ctrl-a:select-all+accept'` — README; `--multi` + `-1`/`--select-1` для «уже однозначно» — man, SCRIPTING.
- **Условный бинд:** `sk --bind 'ctrl-d:if-query-empty(abort)+delete-char'` — man, INTERFACE (эквивалент `delete-char/eof`). Опасность: конфликт с существующим `C-d` Lusty (смена глубины) — не копировать слепо.
- **Превью строки grep с начальным скроллом:** `git grep --line-number '' | sk --delimiter : --preview 'bat --style=numbers --color=always --highlight-line {2} {1}' --preview-window '+{2}-/2'` — man, PREVIEW. Прямой кандидат для serve-клиента Neovim (позиция строки из мета).
- **Внешний порядок:** `history | sk --tac --no-sort`, `sk -f <query>` — man, OPTIONS/SCRIPTING. Для Lusty: `--no-sort` при подаче уже отсортированного списка (frecency/zoxide).
- **Двухступенчатый пайплайн:** `sk --multi | sk --sync` — man, SCRIPTING. Идея для «выбрал папки → наполнил список файлами» без терминального nested-UI.
- **Поля и заголовок:** `ls -l | sk --preview="echo user={3} when={-4..-2}; cat {-1}" --header-lines=1` — man, PREVIEW. Маппинг: long-режим Lusty + превью, собранное из полей meta.
- **skim.vim как конфиг-пример:** `g:skim_layout` принимает ключи `window`, `tmux`, `up`, `down`, `left`, `right`, `options`; `SKIM_DEFAULT_COMMAND` по умолчанию `fd --type f || git ls-tree -r --name-only HEAD || rg --files || ag -l -g "" || find .` — plugin/skim.vim. Для Lusty: набор walker-fallback'ов и «layout в конфиге», а не в коде.
- **Shell-интеграции:** `shell/key-bindings.{bash,zsh,fish}` (Ctrl-T/Ctrl-R/Alt-C аналоги) и генератор `sk --shell <shell> --shell-bindings`; брать как образец, но не вендорить скрипты в Lusty — свой генератор при необходимости.
- **Popup-запуск:** `sk --popup center,50%` (alias `--tmux`) + `bin/sk-tmux` — man/DISPLAY, options.rs. Lusty standalone может получить такой же режим одной опцией, но проверять detect Zellij/Tmux.

Источники примеров: [README](https://github.com/skim-rs/skim/blob/v5.7.4/README.md), [man sk.1](https://github.com/skim-rs/skim/blob/v5.7.4/man/man1/sk.1), [plugin/skim.vim](https://github.com/skim-rs/skim/blob/v5.7.4/plugin/skim.vim), [src/options.rs](https://github.com/skim-rs/skim/blob/v5.7.4/src/options.rs).

## Антипаттерны / что не тащить

- **`--expect` не копировать** — помечен deprecated, заменён биндами `accept(key)`; в новых протоколах нужен `final_key`, а не отдельный список ожидаемых клавиш. Источник: man, DEPRECATED.
- **Дефолтные features «как у CLI»** — `default = ["cli","frizbee","image","listen"]` тянет clap/env_logger в библиотеку; README сам предупреждает, что `cli` библиотеке не нужен. В `lusty-core` не место ни clap, ни crossterm/Tauri; фичи `gui`/`serve`/`listen` — только opt-in.
- **`execute-silent` блокирует UI** до завершения команды (асинхронность — вручную через `&`) — не воспроизводить. Превью и внешние действия Lusty обязаны быть async latest-wins (в текущем TUI уже есть pane_key-механика).
- **PTY-превью по умолчанию на Linux, когда `wrap` выключен** — лишние процессы и PTY на каждый кадр; в Lusty PTY только по явному флагу/GUI.
- **Shell-строки в действиях** — `execute`, `set-preview-cmd`, `set-query`, `--preview` принимают раскрытые выражения и исполняются через `sh -c`; это инъекционная поверхность. В core Lusty действия — типизированные данные, shell — только на фронтенде и только явно.
- **Рекурсивные триггеры и runtime `bind()`/`unbind()`** — сложная семантика (noremap, suppress, конфликты с клавишами); брать статический keymap и нерекурсивные цепочки, runtime-ребиндинг отложить до реальных запросов.
- **Единицы без типов** — `--min-height` игнорируется, если не задан `--height`, и не принимает проценты; отрицательный `--height` значит «term − N». В Lusty — типизированные Size с валидацией на границе.
- **README как истина** — README v5.7.4 говорит «crossbeam channel», исходник использует `kanal`; пинить тег/версию и сверять с кодом.
- **Не искать в skim готовый grid/long** — их нет (только `--multiline`, `--wrap`, scrollbar); компоновку Lusty придётся проектировать самим (fzf/telescope/плагины).
- **Не тащить зоопарк матчеров и typos** — 5 алгоритмов + typo-tolerance это отдельный проект; у Lusty есть fzy + спаны + golden vectors, расширять точечно (`--scheme path`, tiebreak, операторы).

## Открытые вопросы

1. **skim-org** — организация создана 2022-09-13, у неё 0 публичных репозиториев (GitHub API); следа «lotabout/skim → skim-org/skim» не найдено. Подтверждён только перенос `lotabout/skim → skim-rs/skim` (общий repository id 59929513). Где искать официальное решение — issues/wiki (не открывал из-за лимита).
2. **Fzf-паритет действий** — в v5.7.4 отсутствуют `transform` и `change-preview-window`; в `--preview-window` нет `cycle`/`follow`/border-токена. Это осознанно или simply not ported — по коду не видно; вопросы к issues.
3. **`--listen` wire-format** — man говорит про Actions/RON, `--remote` — про строки-цепочки; точный формат, права на сокет, кроссплатформенность не проверены.
4. **`--min-query-length`** — в v5.7.4 чинили «control interactive command runs», но полная семантика (что происходит с уже запущенной командой) не вычитана.
5. **`SkimOutput`/`MatchedItem` API** — `current: Option<MatchedItem>` есть, но какие именно score/span-поля доступны для GUI-подсветки, не проверено (output.rs читал фрагментом).
6. **Формат файла `--history`** (одна строка на запрос? ротация?) не открыт; для Lusty нужно решить свой формат + связать с существующей frecency (`F` в serve).
7. **262 форка** GitHub — какие живые/значимые (встраивания skim как библиотеки, альтернативные UI) не перечислялось из-за лимита обращений.
8. **Tauri-пригодность** — `custom_action_keybinding.rs` показывает callback с `&mut App`, но публичность/стабильность этого API (semver) не проверена; возможно, для GUI хватит только run-loop + каналов.
